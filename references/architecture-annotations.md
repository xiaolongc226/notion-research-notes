# 模型结构图详细标注流程

用户要求给模型结构、数据流或时序图加标记、做详细解释时使用。成果应让读者直接在原图中找到模块，并理解其作用，无需返回聊天补全上下文。按本次请求选择需要的图；下方 Moshi 案例的图数和标记数不作为固定要求。

## 先核对原图和证据

1. 定位原图并查看渲染后的论文页，记录论文版本、PDF 物理页、图号，以及相关图注、公式、表格或实现位置。仅靠提取文本不能确认箭头方向和空间关系。
2. 标注前阅读附近的方法说明，对照实际配置核查简化画法，特别是省略层、示意用的流数量，以及首项输出的特殊处理。示意图与公式存在差异时明确指出，不能自行补造一个看似一致的结构。
3. 梳理输入、变换、中间表示、输出、反馈和训练监督。每条标注保留来源位置，区分原文事实、教学解释和未确定的推断。不补写无依据的维度、参数量、损失函数或因果关系。
4. 在浏览器中工作时使用获准的阅读器，并保留原 PDF；仅在导出工具需要时取得本地副本。论文标题或尚未读取的链接不足以作为证据。

## 标记要解释机制

在原图上放置编号和简短引导线，旁边或下方配套逐项说明。只高亮图注或写一段概要，不能算完成“把结构图标好”。若阅读器仅支持文字高亮，则另行生成带详细标注的图片或文档，并准确说明标注保存在哪里。

按原文实际支持的内容解释：

| 内容 | 读者应能回答的问题 |
|---|---|
| 模块和箭头 | 什么进入模块，执行什么操作，输出什么，传给谁？箭头表示数据流、条件输入、反馈，还是训练目标？ |
| 表示与单位 | 这是波形、特征向量、文本 token、语义码、声学码，还是概率分布？对应哪个采样率、帧率、维度、单位或码本大小？ |
| 训练与推理 | 实际交互时哪些组件运行？哪些教师、损失、判别器或真实标签输入只用于训练？哪些值由模型生成，哪些来自实际观测？ |
| 生成顺序 | 哪条轴推进时间、深度、层数或 token 流？预测每一项时已经知道什么？首个 token 是否通过独立输出头预测？ |
| 时序与延迟 | 哪些索引属于同一原始帧？明确标出延迟；视觉上对齐的行可能对应不同帧。区分理论流式延迟、实测延迟和对话答复等待时间。 |
| 简化画法 | 哪些数量或模块仅用于示意？完整模型配置有什么不同？补画的教学图要标为示意图。 |

每条说明都要指向具体位置。有效的解释包含 **名称 → 操作 → 输入输出或依赖 → 关键边界**，而不只是展开缩写。颜色保持一致，同时使用编号或文字，不能只靠颜色区分含义。

## 保持可读，并维护同一份标注内容

- 保留原图标签、相关图例和箭头尖端；裁剪不能移除影响理解的信息。引导线落点若会遮住文字，改放在模块边界或空白位置。避免穿过标签、公式和其他标记。
- 长解释放在原图外。图过密时放大或分拆页面，不要把标签缩小到难以阅读。按图的形状选择布局，横版可用但不是强制格式。
- 尽量保留矢量内容，或使用足够清晰的裁剪图；嵌入支持目标语言的字体。不要用生成式图片编辑重建科学标签或公式。
- 需要多种导出时，维护一份标注清单，包含图号和页码、原图及裁剪坐标、标记编号、目标位置、标题、解释和证据。说明坐标使用 PDF 点还是裁剪区域内的归一化坐标。PDF、图片预览和文字解释从同一清单生成，避免编号或内容漂移。
- 保留原始文件，把新增说明标为阅读标注；导出文件与源 PDF 分开存放。

## 检查文件与实际交付

渲染每一页标注结果，排版调整后重新查看。确认每个编号指向预期位置，并有唯一对应解释；原标签清晰可见，说明没有裁断，字体正常，时间索引及定量结论与来源一致。页数或标记数量一致，不代表内容正确。

按用户要求交付标注 PDF 或图片集。适合浏览器阅读、或 PDF 预览失败时，可提供含完整尺寸图片与文字解释的 HTML 预览；密集页面可增加放大和展开说明功能。离线版本应内嵌图片，或用相对路径一起打包，检查其不依赖临时预览服务。离线页面内的导航、下载链接应指向打包文件，或去掉仅在线服务可用的按钮。

验证实际交付入口，不能只确认文件已生成：用用户可用的浏览器或应用打开链接、查看可见内容，并核对下载文件完整。回环地址只是本机临时预览，不是长期公开链接；同时保留离线文件。预览卡住时换用支持的格式，不反复提交同一条被阻塞的操作；交付时说明哪种展示已经验证。

若用户要求发布到 Notion 或其他目的地，按该平台支持的方式上传标注媒体并检查实际展示。不要把本地路径或回环地址当作远程图片来源。本流程不扩大外发或修改无关内容的授权。

## 参考案例：Moshi

Moshi 精读展示的是解释尺度，不能把它的模型事实套到其他论文。本次选取四张图，共做了 36 处编号标记；其他材料可以需要更少或更多。

| 原图 | 标注应解释清楚的关键区别 |
|---|---|
| [图 1，第 7 页](https://arxiv.org/pdf/2410.00037v2#page=7&search=Overview%20of%20Moshi&phrase=true) | 沿用户音频、Mimi、历史 embedding、时间上下文、文本及音频生成、输出解码器追踪数据流。 |
| [图 2，第 10 页](https://arxiv.org/pdf/2410.00037v2#page=10&search=Architecture%20and%20training%20of%20Mimi&phrase=true) | 区分语义 VQ 与声学 RVQ，以及因果运行路径与只在训练中使用的教师、损失分支。 |
| [图 3，第 13 页](https://arxiv.org/pdf/2410.00037v2#page=13&search=Architecture%20of%20the%20RQ-Transformer&phrase=true) | 区分时间轴与当前时间步内部生成，图示 K=4 与完整的 17 路表示，以及正文公式规定的首项 token 线性输出头。 |
| [图 4，第 15 页](https://arxiv.org/pdf/2410.00037v2#page=15&search=Representation%20of%20the%20joint%20sequence%20modeled%20by%20Moshi&phrase=true) | 同一列可以包含当前语义 token 与延迟的声学 token。结合 §3.4.2—3.4.4，解释 80 ms 音频帧和一帧声学延迟如何构成理论 160 ms。 |

可复用的方式是：**原图 → 定位标记 → 有证据的解释 → 容易误读的依赖或边界 → 验证过的可读导出**。更换论文或版本时重新核对原文。
